3. API BASE URL CENTRALIZATION (REFACTOR)
================================================================================
Previously `http://localhost:5000` was hardcoded in 15 places across 6 files.
This made it impossible to change the backend URL without editing every file.

CHANGE: All API calls now import from a single config:
  - Frontend/src/config.js  (NEW FILE)
      export const API_BASE = import.meta.env.VITE_API_URL || 'http://localhost:5000'

  - The URL is read from Frontend/.env (VITE_API_URL)
  - To change the backend URL (e.g. for production), edit Frontend/.env only.

Files updated:
  - Frontend/src/Admin/Admin.jsx
  - Frontend/src/Home/Home.jsx
  - Frontend/src/Booking/Booking.jsx
  - Frontend/src/Login/Login.jsx
  - Frontend/src/Registration/Registration.js

================================================================================
4. ADMIN PASSWORD MOVED TO BACKEND (SECURITY)
================================================================================
Before: The admin password `admin123` was hardcoded in client-side JS
(Frontend/src/Admin/Admin.jsx), visible to anyone viewing the browser source.

After:
  - Backend/routes/auth.js  ADDED NEW ENDPOINT:
      POST /api/auth/admin-login
        body: { "password": "..." }
        Checks password against process.env.ADMIN_PASSWORD (from Backend/.env)
        Returns { success: true } on match, 401 on mismatch.
  - Frontend/src/Admin/Admin.jsx `handleLogin` now calls this endpoint
    instead of comparing to a hardcoded string.
  - The password now lives ONLY in Backend/.env

To change the admin password, edit ADMIN_PASSWORD in Backend/.env.

12. KNOWN REMAINING ISSUES (NOT FIXED / OUT OF SCOPE)
================================================================================
These work but could be improved in a future pass. Documented for awareness:
- Admin.jsx is still a large (1300+ line) component — could be split into tabs.
- Home.jsx is large (940+ lines) — could be split into section components.
- Images (crew photos, project images, payment slips) are stored as base64 in
  MongoDB — consider cloud storage (S3/Cloudinary) for production.
- No server-side auth middleware protects /api/projects, /api/bookings,
  /api/crew CRUD endpoints (anyone can call them directly).
- JWT_SECRET has a fallback default in auth.js — set a strong value in .env.
- Backend response formats are inconsistent (some return raw arrays, some wrap
  in { success, message, data }).
- No test framework is configured.

HOW TO SET UP AFTER CLONING
================================================================================
Backend:
  1. cd Backend
  2. cp .env.example .env  (then fill in real values)
  3. npm install
  4. npm run dev

Frontend:
  1. cd Frontend
  2. npm install
  3. (optional) create .env with VITE_API_URL=http://localhost:5000
  4. npm run dev

Admin login password: configured via ADMIN_PASSWORD in Backend/.env
